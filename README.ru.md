# LoKi

Русский · [English](README.md)

> **Приложение находится в стадии активной разработки.** Каждый программный этап проверяется на Linux перед согласованием и merge. Испытания на роутере проходят после завершения программных этапов. Стабильность на OpenWrt и поведение при отказах DNS/TLS ещё не подтверждены лабораторными испытаниями.

Маршрутизация трафика OpenWrt по правилам с помощью sing-box. LoKi — независимо развивающийся форк [Forkop](https://github.com/ushan0v/forkop) на базе версии 2.0.0, коммит `9544f3de09c62c935e1147147136234594d04f02`.

Репозиторий проекта — [Zagorsky17/LoKi](https://github.com/Zagorsky17/LoKi). Ошибки и предложения принимаются в [LoKi Issues](https://github.com/Zagorsky17/LoKi/issues).

## Состояние разработки

На 02.11.2026 в репозитории нет релиза LoKi. Установщик получает приложение и исправленное ядро из **`Zagorsky17/LoKi`**, без возврата к релизам Forkop. Для установки нужен релиз с пакетами, `release.json`, `core-release.json` и `SHA256SUMS`; одной публикации исходников в `main` недостаточно. Приложение требует собственную сборку ядра `1.14.4-r3` или новее; техническое имя пакета пока `sing-box-forkop`. Установка и обновление на роутере ещё не проверены.

В исходниках пока используются технические имена `forkop`, `luci-app-forkop` и `/etc/config/forkop`. Их согласованная замена запланирована. LoKi предназначен для чистой установки с собственной конфигурацией; переходы с Forkop, Podkop и других приложений не поддерживаются. Миграции Forkop 1.0.x и автоматическая замена пакетов/конфигурации другого проекта удалены. Обязательная отдельно запускаемая проверка конфликтов перед установкой пока не реализована; установка ещё не готова к рабочему использованию.

## Планируемые возможности

В LoKi останутся ссылки подключений, подписки, секции маршрутизации, DNS, мониторинг и диагностика. Размещение VPN/прокси-серверов на роутере удалено: отсутствуют серверная вкладка, генерация слушателей, выдача клиентских профилей, генерация серверных ключей и серверная диагностика. Встроенные входы DNS/TProxy и исходящие подключения сохранены. Встроенные клиентские VPN-туннели (WireGuard, AmneziaWG, WARP, Tailscale, OpenVPN и OpenConnect) и JSON endpoint также удалены. Ссылки подключений, подписки, JSON outbound и существующие сетевые интерфейсы сохранены; ручной JSON outbound не может вернуть удалённые типы VPN. Остаётся только механизм будущих миграций самого LoKi.

Целевые версии — OpenWrt 24.10 и 25.12. Полная адаптация к штатным ядрам продолжается. Ограниченные профили ручного JSON и обычных HTTP(S)/SOCKS-ссылок с одним основным и одним bootstrap DNS и выключенным unified delay проходят проверку схемы официальным Linux 1.14.4. Проверенные обычные формы ASCII-ссылок преобразуются в стандартные outbounds; сложные формы сохраняют действующий parser и исходные данные. Подписки, DNS fallback и активный unified delay всё ещё требуют расширений ядра. Текущая разработка использует исправленное ядро LoKi в пакете `sing-box-forkop`.

На Linux исходная проверка схем запускается командой `python3 core/tests/compatibility.py REFERENCE_R3 STOCK_BINARY_DIR OUTPUT_DIR`. Замените `REFERENCE_R3` путём к доверенному бинарнику r3, `STOCK_BINARY_DIR` — каталогом с официальными архивами из `core/tests/compatibility_releases.json` и их бинарниками, переименованными в `sing-box-VERSION`, а `OUTPUT_DIR` — каталогом результатов. До исполнения проверяются digest архивов и байты извлечённых файлов. Ожидаются 32 проверки: r3 принимает все восемь профилей, официальный 1.14.4 — ограниченный ручной и три профиля обычных ссылок, остальные штатные случаи отклоняют известные расширения схемы. Пустой providers и неактивные поля кэша подписок/unified delay не выдаются. Это не подтверждает работу приложения со штатным ядром; зависимости пакетов и требования запуска по-прежнему требуют r3.

Внешними зависимостями остаются встроенные списки [forkop-lists](https://github.com/ushan0v/forkop-lists) и диагностические домены `ip.podkop.fyi` и `fakeip.podkop.fyi`.

## Резервные копии конфигурации

Конфигурация LoKi содержит `option config_format 'loki'` вместе с версией схемы. Совпадение номера версии не делает конфигурацию Forkop или Podkop совместимой. Установочный вызов миграции, старт и восстановление копии отклоняют чужую, неподдерживаемую или повреждённую схему без переноса и сброса файла. Промежуточные конфигурации разработки без идентификатора LoKi автоматически не преобразуются.

Загрузка восстанавливает собственную копию LoKi как несохранённые изменения текущей сессии LuCI; они вступают в силу после применения. Загружаемый файл должен быть обычным файлом размером не более 1 МиБ. Текущая конфигурация не требует миграции; для будущих версий LoKi сохранены общий механизм и резервные копии с закрытыми правами. Это не заменяет запланированную проверку конфликтов среды. Ссылки подключений и подписки остаются отдельными поддерживаемыми входами; глобальные настройки другого клиента не импортируются.

## Настройки DNS в разрабатываемой версии

В разрабатываемом интерфейсе режим шифрования задаётся явно для всего основного списка DNS: «Выключено (UDP)» либо «Включено» с обязательным выбором DoH или DoT. Адреса должны соответствовать выбору: `https://dns.example/dns-query` для DoH, `tls://dns.example` для DoT, IP-адрес для UDP. `dns.example` — учебное имя; укажите адрес своего резолвера. Смена режима не переписывает адреса и не переключает протокол при отказе сервера.

Bootstrap использует UDP по IP. Имена исходящих соединений без собственного резолвера разрешаются через bootstrap; явные настройки JSON и интерфейсов сохраняются. Новая конфигурация сохраняет прежний режим UDP. Для старых настроек без поля шифрования протоколы в адресах продолжают действовать, а при редактировании интерфейс требует явного выбора режима. Эти изменения ещё требуют проверки на лабораторном OpenWrt.

Для исходящих подключений с явным резолвером исправленное ядро начинает соединение по готовой семье адресов, не ожидая таймаута другой. При отказе или задержке подключения сохраняется резервная попытка по второй семье; `ipv4_only` и `ipv6_only` сохраняют свой смысл. Это касается также разрешения имени DoH/DoT-сервера. Обычный обход DNS-правил продолжает получать полный результат; переход на UDP или прямой выход при отказе не добавлен.

Перехваченные PTR-запросы используют локальный резолвер для локально обслуживаемых обратных зон и текущих IPv4/IPv6-префиксов интерфейсов перехвата LAN, включая публичные префиксы LAN. Остальные PTR следуют выбранным DNS-правилам. Если снимок адресов LAN недоступен, повреждён или превышает ограничения, в журнал выводится предупреждение, а все PTR сохраняют прежний локальный маршрут. Префиксы обновляются при старте или reload службы; после смены адресации LAN повторно примените настройки. Режим `router` продолжает отправлять несовпавшие запросы локальному резолверу. Это поведение ещё требует проверки на OpenWrt.

## Сборка ядра

В `core/` находятся патчи, тесты и сборочные скрипты. Исходники sing-box-forkop закреплены на коммите `60d96c99815a672712915a5c00114bf0f690ad80`; архив проверяется по SHA-256 до распаковки, патч проверяется перед применением. Автоматического обновления исходников нет. Полный код ядра не копируется в репозиторий LoKi; каждая пакетная сборка также создаёт `core-source-VERSION.tar.gz` с деревом после патча для распространения рядом с бинарными файлами.

Сборка выполняется на Linux с Go из `core/GO_VERSION`, Bash, Git, curl, Python 3 и инструментами существующей пакетной сборки. Пример ниже создаёт пакеты приложения и ядро base для `aarch64_cortex-a53`; `0.1.0` — пример версии, а не опубликованный релиз. После сборки приложения инструмент apk берётся из стандартного кэша SDK; при другом каталоге SDK замените путь.

```sh
./build.sh 0.1.0 "$PWD/release"
export PATH="$HOME/.cache/forkop/openwrt-sdk/extracted/apk/staging_dir/host/bin:$PATH"
core/build.sh 0.1.0 "$PWD/release" --arch aarch64_cortex-a53 --variant base
(cd release && sha256sum -c SHA256SUMS)
```

`core/build.sh` принимает варианты и цели унаследованного сборщика; без ограничения архитектуры собираются все его цели. Вариант full может дополнительно загружать несколько гигабайт исходников и инструментов Chromium. Workflow релиза добавляет варианты tiny/base/full и отдельный манифест ядра к файлам приложения. Сборка не публикует релиз и не устанавливает пакеты.

Проверки: `core/test.sh -race -count=1` и `python3 core/tests/test_release.py`. Команда `python3 core/tests/dns_bootstrap.py /путь/к/sing-box /каталог/результатов` требует ucode и запускает синтетические DNS, TLS и прокси только на loopback. Команда `python3 core/tests/log_repeats.py /путь/к/sing-box /каталог/результатов` проверяет повторы отказов TCP, смену 10-секундного окна и сводку при остановке. Результаты сохраняются в указанном каталоге; эти проверки не заменяют OpenWrt.

## Диагностические отчёты

При применении настроек и в проверке службы появляется предупреждение, если встроенный список и распознанная внешняя ссылка в одной включённой секции используют один источник или могут пересекаться. Проверяются точные канонические ссылки forkop-lists, короткие имена встроенных списков и две исторические ссылки itdog (`russia_inside.srs`, `meta.srs`). Предупреждение не доказывает одинаковое содержимое разных файлов: сравните домены и подсети перед удалением списка. Сохранение не блокируется, списки и маршрутизация автоматически не меняются; неизвестные URL и локальные файлы не загружаются для сравнения. Полные внешние URL и токены в новые предупреждения и поля ответа не попадают. Это диагностика, а не уменьшение расхода памяти.

FakeIP связывает синтетический IP-адрес с доменным именем для маршрутизации. В проверке «Трафик» отрицательный результат браузерной проверки FakeIP показывается нейтральным замечанием и сам по себе не помечает раздел как проблемный. Он не определяет настройки DNS устройства. Отсутствие ответа проверки остаётся предупреждением; ошибки роутера и выхода сохраняют свою серьёзность. В текстовом отчёте замечание отмечено символом ℹ.

Ядро LoKi сворачивает точные повторы ERROR одного компонента в окне 10 секунд: первая ошибка видима сразу, повторы учитываются в числовой сводке. Кэш ограничен 64 парами отпечатков компонента и сообщения; исходный текст не хранится. Новые ошибки при заполненном кэше, остальные уровни и FATAL/PANIC остаются видимыми. Сводка появляется со следующей записью после окончания окна либо при штатной остановке; отдельного таймера нет. Аварийное завершение может потерять ещё не выведенную сводку. Различающиеся тексты не объединяются, поэтому это не общее ограничение всего потока журнала.

Проверка службы показывает число сообщений ERROR/FATAL sing-box, найденных за последние 60 секунд в доступном журнале. Счётчик считает записи, а не сетевые отказы: сводка повторов DNS считается одной записью. Чтение выполняется по запросу, ограничено 64 КиБ и 1000 строками; при ограничении или повреждённых данных показана неполнота, при ошибке чтения — недоступность. История и отдельные файлы журнала не создаются, текст строк в новое поле ответа не передаётся. Вытеснение записей из logd и изменение системного времени ограничивают точность; сам счётчик поток сообщений не уменьшает.

Ошибки валидации DNS указывают место настройки и причину без исходного DNS URI. Отчёт открывается с замаскированными значениями. Для просмотра без маскирования требуется подтверждение; первая строка предупреждает о ключах и паролях. Копирование и скачивание отключены на время переключения, затем сохраняют показанный режим. Для передачи используйте masked или `forkop report masked` и просматривайте содержимое перед отправкой: маскирование не распознаёт любой возможный секрет. Обновляйте пакеты бэкенда и LuCI вместе, чтобы форматы отчёта совпадали.

На Linux команда `python3 core/tests/plain_links.py CORE OUTPUT_DIR [REFERENCE_R3]` сравнивает сгенерированные HTTP(S)/SOCKS outbounds с действующим parser на локальных прокси с авторизацией, включая отказы при неверном пароле и недоверенном сертификате. Передайте пути к доверенным, проверенным бинарникам и новый каталог результатов; для официального 1.14.4 в `CORE` укажите r3 в `REFERENCE_R3`. Тест меняет только собственные слушатели и файлы.

Сгенерированные каскады проверяются командой `python3 core/tests/cascade_links.py CORE NEW_OUTPUT_DIR [REFERENCE_R3]` с теми же доверенными бинарниками. Она проверяет HTTP/HTTPS на первом прокси и HTTP/HTTPS/SOCKS5 на конечном, недоступность обоих узлов, отказы авторизации/TLS, обрыв и восстановление. Намеренно удалённый detour должен обнаруживаться даже при успешном конечном ответе. Все endpoints локальные; это не подтверждает маршрутизацию роутера или все виды каскадов.

## Документация и проверки

Публичная документация проекта ведётся в этом README и [README.md](README.md). Унаследованный сайт документации и workflow публикации в GitHub Pages удалены.

Тесты и сборки пакетов выполняются на выделенном Linux-сервере разработки. Отказы DNS, перехват трафика и установку перед релизом дополнительно проверяют на лабораторном OpenWrt. Для тестов безопасности используются синтетические реквизиты и локальные тестовые сервисы.

Исходный Forkop разработан [ushan0v и участниками проекта](https://github.com/ushan0v/forkop/graphs/contributors). LoKi развивается независимо в [Zagorsky17/LoKi](https://github.com/Zagorsky17/LoKi) и не является релизом исходного Forkop.

LoKi сохраняет лицензию проекта [GPL-2.0-or-later](LICENSE). Патч ядра и собираемое ядро sing-box-forkop распространяются отдельно по [GPL-3.0-or-later](core/COPYING); соответствующий исходный код состоит из закреплённого upstream и патча `core/patches/`. Существующие уведомления об авторских правах, лицензиях и авторстве сохраняются. У сторонних компонентов действуют собственные уведомления, в том числе у [встроенных файлов шрифта](luci-app-forkop/htdocs/luci-static/resources/view/forkop/fonts/LICENSE.md).

При распространении изменённых версий и бинарных пакетов необходимо сохранить применимые уведомления и лицензию, обозначить изменённые файлы и даты правок, предоставить соответствующий исходный код согласно [GNU GPL версии 2](https://www.gnu.org/licenses/old-licenses/gpl-2.0.en.html).
